# Правила работы с литературой и ссылками

## Главный принцип

Список литературы должен подтверждать теоретическую и методическую часть ВКР. Источники нужны не для формальности, а чтобы показать, на чем основаны утверждения о поиске, embeddings, базах знаний, архитектуре backend-сервисов, PostgreSQL/pgvector и оформлении ВКР.

Перед добавлением источника агент обязан:

1. Проверить `docs/reports/correlation.md`.
2. Если источник уже есть, использовать существующий номер.
3. Если источник новый, добавить его в раздел `Реестр источников`.
4. Пометить источник статусом:
   - `проверен` - библиографические данные подтверждены;
   - `требует проверки` - источник полезен, но данные нужно сверить перед финальной сдачей.

## Формат ссылок в тексте

Использовать квадратные ссылки:

- `... методы оценки информационного поиска рассматриваются в [1].`
- `... требования к структуре отчета определяются ГОСТ 7.32-2017 [5].`
- `... расширение pgvector поддерживает хранение и поиск по векторам в PostgreSQL [8].`

Если утверждение опирается на несколько источников:

- `... [1, 3, 8]`.

## Типы источников

Для ВКР желательно иметь не менее 20-30 источников, среди них:

- учебники и монографии на русском языке;
- научные статьи на русском языке;
- ГОСТ и методические документы;
- официальная документация XWiki, Spring Boot/Spring AI, PostgreSQL, pgvector, Ollama;
- технические статьи как вспомогательные источники, но не вместо научной базы.

## Стартовый список источников-кандидатов

Эти источники можно использовать как основу, но перед финальной вставкой в ВКР нужно сверить библиографические данные с библиотекой, eLIBRARY, издателем или официальным сайтом.

1. Маннинг К. Д., Рагхаван П., Шютце Х. Введение в информационный поиск. - М.: Вильямс, 2011. Статус: `требует проверки`.
2. ГОСТ 7.32-2017. Система стандартов по информации, библиотечному и издательскому делу. Отчет о научно-исследовательской работе. Структура и правила оформления. Статус: `требует проверки`.
3. ГОСТ Р 7.0.100-2018. Библиографическая запись. Библиографическое описание. Общие требования и правила составления. Статус: `требует проверки`.

5. ГОСТ Р 7.0.108-2022. Библиографические ссылки на электронные документы. Общие требования к составлению и оформлению. Статус: `требует проверки`.
6. Документация XWiki REST API. Статус: `требует проверки`.
7. Документация Spring Boot. Статус: `требует проверки`.
8. Документация Spring AI Ollama. Статус: `требует проверки`.
9. Документация PostgreSQL. Статус: `требует проверки`.
10. Документация pgvector. Статус: `требует проверки`.
11. Документация Ollama. Статус: `требует проверки`.
12. Мелихов А. Оформление ВКР: что важно помнить студенту? // Хабр. 2023. URL: https://habr.com/ru/companies/ncloudtech/articles/728628/. Статус: `проверен как веб-источник`.

## Где нужны ссылки в главах

Введение:

- источники об актуальности корпоративных баз знаний и информационного поиска;
- источники по ВКР/ГОСТ при описании структуры не обязательны, но могут быть использованы.

Глава 1:

- информационный поиск;
- полнотекстовый поиск;
- семантический поиск;
- embeddings;
- метрики качества поиска.

Глава 2:

- архитектура REST-сервисов;
- PostgreSQL/pgvector;
- XWiki REST API;
- Docker/контейнеризация.

Глава 3:

- документация используемых технологий;
- ссылки на Spring Boot, Spring AI, Ollama, XWiki, PostgreSQL.

Глава 4:

- источники по evaluation метрикам: MRR, Hit@K, nDCG;
- ссылки на сформированные собственные отчеты и приложения.

## Правила для русскоязычных научных статей

Если пользователь просит добавить научные статьи на русском языке, агент должен:

- искать статьи по ключевым словам: `информационный поиск`, `семантический поиск`, `векторные представления текста`, `оценка качества поиска`, `поиск по базе знаний`, `обработка естественного языка`;
- отдавать приоритет журналам, сборникам конференций, eLIBRARY, КиберЛенинке, ВАК-журналам;
- не включать статью в список литературы без авторов, названия, года и источника публикации;
- помечать источник `требует проверки`, если библиографические данные взяты не с официальной страницы.

## Как оформлять веб-источники

Минимальный шаблон:

```text
Автор. Название страницы [Электронный ресурс]. - URL: ... (дата обращения: ДД.ММ.ГГГГ).
```

Для текущей даты использовать фактическую дату обращения. Если агент не уверен в дате, указывать текущую дату из окружения.

## Недопустимые источники

Не использовать как научную основу:

- случайные пересказы без автора;
- ответы форумов без проверки;
- рекламные статьи как доказательство научных тезисов;
- Wikipedia как основной источник для определения ключевых понятий;
- непроверенные PDF без выходных данных.
