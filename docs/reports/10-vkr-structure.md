# Рекомендуемая структура ВКР

## Тема и рабочая формулировка

Рабочая тема: `Разработка сервиса семантического поиска по базе знаний XWiki с использованием векторных представлений текста`.

Допустимые уточнения темы:

- `... на основе Spring Boot, Ollama и PostgreSQL/pgvector`;
- `... с экспериментальной оценкой качества поиска`;
- `... для повышения релевантности поиска в корпоративной базе знаний`.

## Логика всей работы

Текст должен строиться как доказательство:

1. В корпоративной базе знаний XWiki стандартный поиск может не находить релевантные страницы при неполном или переформулированном запросе.
2. Семантический поиск на embeddings позволяет сравнивать запрос и документы по смысловой близости.
3. Для реализации выбран подход: XWiki REST API + нормализация контента + чанкинг + Ollama embeddings + pgvector + REST API поиска.
4. Разработанный сервис интегрирован с XWiki и локальным Docker-окружением.
5. Качество проверено на датасете запросов и сравнено со стандартным XWiki Solr.
6. Полученные метрики показывают практическую эффективность подхода и ограничения дальнейшего развития.

## Введение

Во введении раскрыть:

- актуальность: рост объема корпоративных знаний, сложность поиска по wiki, ограниченность точного совпадения слов;
- объект исследования: процессы поиска информации в базе знаний XWiki;
- предмет исследования: методы семантического поиска по текстовым документам с использованием векторных представлений;
- цель: разработать и оценить сервис семантического поиска по XWiki;
- задачи:
  - проанализировать предметную область и существующие подходы к поиску;
  - выбрать архитектуру сервиса;
  - реализовать загрузку и обработку страниц XWiki;
  - реализовать построение и хранение embeddings;
  - разработать REST API поиска;
  - подготовить методику оценки и сравнить качество с XWiki Solr;
- методы: анализ литературы, проектирование backend-сервиса, REST-интеграция, векторный поиск, экспериментальная оценка метрик;
- практическая значимость: повышение релевантности поиска по базе знаний;
- структура работы: кратко перечислить главы.

Рекомендуемый рисунок:

```text
Рисунок N - Роль разработанного сервиса в контуре поиска по базе знаний
Prompt для рисунка: Создать академическую схему на русском языке в едином строгом стиле. Показать пользователя, XWiki как базу знаний, разработанный Spring Boot сервис семантического поиска, PostgreSQL/pgvector, Ollama. Стрелками показать: пользователь отправляет запрос в сервис; сервис получает embedding запроса через Ollama; сервис ищет близкие chunks в pgvector; возвращает релевантные страницы XWiki. Белый фон, тонкие линии, синие и серые акценты, без декоративных элементов.
```

## Глава 1. Анализ предметной области и постановка задачи

Цель главы - показать, почему задача существует и какие подходы применимы.

Рекомендуемые подразделы:

1. `Корпоративные базы знаний и особенности поиска в XWiki`.
2. `Полнотекстовый поиск и его ограничения`.
3. `Семантический поиск и векторные представления текста`.
4. `Сравнение подходов к реализации поиска`.
5. `Постановка задачи и критерии качества`.

Обязательные материалы:

- таблица сравнения полнотекстового, семантического и гибридного поиска;
- рисунок pipeline семантического поиска;
- ссылки на литературу по информационному поиску, embeddings, pgvector/vector search.

Пример вывода по главе:

> В первой главе установлено, что полнотекстовый поиск эффективен при точном совпадении терминов, однако хуже обрабатывает переформулированные запросы. Для повышения релевантности поиска по базе знаний XWiki целесообразно использовать векторные представления текстовых фрагментов и ранжирование по близости между запросом и документом.

## Глава 3. Реализация программного решения

Цель главы - описать не весь код подряд, а ключевые инженерные решения.

Рекомендуемые подразделы:

1. `Интеграция с XWiki REST API`.
2. `Нормализация и разбиение контента на чанки`.
3. `Формирование embeddings и сохранение в pgvector`.
4. `Реализация семантического поиска`.
5. `REST API разработанного сервиса`.
6. `Вспомогательные Python-инструменты`.

Обязательные материалы:

- листинг controller endpoint `/api/xwiki/search`;
- листинг фрагмента ingestion embeddings;
- листинг SQL-запроса поиска ближайших chunks;
- таблица основных Java-классов и их ответственности;
- рисунок sequence diagram для запроса поиска;
- приложение с расширенными листингами, если код занимает больше 1 страницы.

Правило: в основной текст включать только короткие листинги, которые объясняются в тексте. Полные классы переносить в приложения.
