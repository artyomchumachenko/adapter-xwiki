# Правила итерационного написания ВКР

## Структура ВКР

Основной текст ВКР должен состоять из четырех глав:

1. `ГЛАВА 1 АНАЛИЗ ПРЕДМЕТНОЙ ОБЛАСТИ И ТЕОРЕТИЧЕСКИЕ ОСНОВЫ`
2. `ГЛАВА 2 ПОСТАНОВКА ИССЛЕДОВАНИЯ И МЕТОДИКА ОЦЕНКИ`
3. `ГЛАВА 3 ПРОЕКТИРОВАНИЕ И РЕАЛИЗАЦИЯ СИСТЕМЫ`
4. `ГЛАВА 4 ЭКСПЕРИМЕНТАЛЬНАЯ ОЦЕНКА И СРАВНИТЕЛЬНЫЙ АНАЛИЗ`

## Рабочая структура файлов

Для каждой главы используется отдельная папка:

```text
docs/vkr/1/
docs/vkr/2/
docs/vkr/3/
docs/vkr/4/
```

Внутри каждой папки:

- `00-plan.md` - план главы, обязательный первый файл;
- `01-*.md`, `02-*.md`, ... - итерационные файлы с текстом отдельных разделов;
- `90-chapter-summary.md` - выводы по главе;
- `99-chapter-final.md` - связанная финальная сборка главы, создается только после закрытия всех разделов.

Пример:

```text
docs/vkr/1/00-plan.md
docs/vkr/1/01-knowledge-bases-and-xwiki.md
docs/vkr/1/02-full-text-search-limitations.md
docs/vkr/1/03-semantic-search-and-embeddings.md
docs/vkr/1/90-chapter-summary.md
docs/vkr/1/99-chapter-final.md
```

## Обязательный порядок работы над главой

### Шаг 1. Создать или актуализировать план главы

Перед написанием текста главы агент должен создать или заполнить `00-plan.md`.

В плане должны быть:

- цель главы;
- список разделов и подразделов;
- ожидаемый объем каждого раздела в знаках с пробелами;
- список необходимых рисунков, таблиц, листингов и приложений;
- список источников литературы;
- логика перехода от предыдущей главы и к следующей главе;
- критерии закрытия главы.

Если `00-plan.md` пустой или содержит только шаблон, писать разделы запрещено.

### Шаг 2. Перед новой итерацией прочитать контекст главы

Перед созданием очередного файла `NN-*.md` агент обязан прочитать:

- `00-plan.md` текущей главы;
- все ранее созданные `NN-*.md` файлы этой главы;
- `90-chapter-summary.md`, если он уже есть;
- `docs/vkr-control/progress.md`;
- `docs/reports/correlation.md`.

После чтения агент должен явно учитывать:

- какие тезисы уже раскрыты;
- какие понятия уже определены;
- какие рисунки, таблицы и листинги уже использованы;
- какой логический переход нужен от предыдущего файла;
- что именно нельзя повторять.

### Шаг 3. Создать итерационный файл

Каждый итерационный файл должен начинаться с технической шапки:

```markdown
# <Название раздела>

## Паспорт итерации

- Глава: <номер и название>
- Разделы плана: <какие пункты закрывает файл>
- Целевой объем: <N знаков с пробелами>
- Фактический ориентир: <кратко>
- Предыдущий контекст: <какие файлы главы учтены>
- Новые материалы: <рисунки/таблицы/листинги/источники>
- Статус: черновик
```

После шапки идет текст раздела. В конце файла обязательны:

```markdown
## Логический переход

<2-4 предложения, которые связывают этот раздел со следующим.>

## Что закрыто

- <тезис 1>
- <тезис 2>
- <тезис 3>

## Что не повторять дальше

- <уже раскрытая мысль>
- <уже использованный пример>
```

### Шаг 4. Обновить прогресс

После создания или существенного изменения файла агент обязан обновить `docs/vkr-control/progress.md`:

- изменить статус раздела;
- указать файл, в котором раздел раскрыт;
- указать примерный объем;
- отметить использованные таблицы, рисунки, листинги и источники;
- записать, что осталось до закрытия раздела.

### Шаг 5. Закрытие раздела

Раздел можно пометить `закрыт`, только если выполнены все условия:

- раздел раскрывает вопрос из плана;
- нет очевидных повторов с предыдущими файлами главы;
- есть ссылка на нужные источники или отмечено, что источник требуется;
- при необходимости добавлены таблица, рисунок, листинг или prompt для рисунка;
- текст содержит вывод или логический переход;
- объем находится в пределах бюджета раздела: допустимое отклонение `-15% / +10%`;
- `correlation.md` обновлен, если добавлены нумерованные объекты.

### Шаг 6. Закрытие главы

Глава считается закрытой, когда:

- все разделы в `00-plan.md` имеют статус `закрыт`;
- создан `90-chapter-summary.md` с выводами по главе;
- создан `99-chapter-final.md`, где глава собрана в связный текст без технических шапок итераций;
- нет дублирования между разделами;
- все рисунки, таблицы, листинги, приложения и источники отражены в `correlation.md`;
- объем главы не превышает бюджет из `volume-budget.md`;
- в конце главы есть выводы, из которых логически следует следующая глава.

## Правило недублирования

Запрещено начинать новый файл с повторного пересказа уже написанного.

Разрешено кратко напомнить контекст в 1-2 предложениях, если это необходимо для связности:

```text
Ранее были рассмотрены ограничения полнотекстового поиска. Далее анализируется подход семантического поиска, позволяющий частично устранить указанные ограничения за счет представления текста в виде векторов.
```

Нельзя повторять целый абзац о том же самом.

## Правило связности

Каждый файл должен продолжать предыдущий:

- в начале указать, на какой вывод предыдущего раздела он опирается;
- в конце подготовить переход к следующему разделу;
- не менять терминологию без причины;
- использовать одинаковые названия компонентов проекта.

## Правило финальной сборки

`99-chapter-final.md` создается только после завершения всех итерационных файлов главы.

При сборке:

- удалить технические шапки `Паспорт итерации`;
- сохранить академический текст;
- объединить повторяющиеся определения;
- проверить нумерацию материалов;
- проверить, что выводы главы не противоречат тексту;
- не добавлять новые крупные тезисы без отдельной итерации.
